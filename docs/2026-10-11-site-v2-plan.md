# Site v2 Plan: from one game to a full arcade

Written 2026-10-11. This file will be saved as `docs/2026-10-11-site-v2-plan.md`.
Because this repo is public, this plan says "parent" instead of names, and it leaves out the Drive link and the original file names (some of them are brand names).

## Context

digdeeperlabs.com has one game today: Pinball. It has a working leaderboard in a Google Sheet. Emmet has nine more games in a Drive folder. The goal is a real arcade:
- every game on the site,
- one shared leaderboard all games use,
- a home page that feels like an arcade.

**How every phase works.** Each phase is small. Each one ends with the site still working and a **save point**. Emmet writes the commit message, clicks Commit, then Sync Changes, then checks the live site. Every feature starts in plan mode with the usual habits:
- the architect questions,
- predict, then test with Go Live,
- name the dials,
- one change Emmet types himself.

**Live leaderboard rule.** Any phase that changes the Apps Script gets two steps:
- **Before:** Claude tells the parent exactly what will change for the live pinball game.
- **After:** the parent updates the deployment. In Apps Script, go to Deploy > Manage deployments > pencil icon > Version: **New version** > Deploy. Do **not** click "New deployment". That makes a new web address, and the live game would keep calling the old one.

## How the pinball leaderboard works today (plain words)

There are three pieces:

1. **The game** (`pinball/leaderboard.js`) knows one web address: the sheet's web app.
   - To *read*, it asks that address and gets back the top 15.
   - To *save*, it sends `{ initials, score }`.
   - If nothing answers in 8 seconds, it says "Leaderboard offline" and the game keeps going.
2. **The Apps Script** (the copy in the repo is `pinball/leaderboard-script.gs`) is the bouncer at the door.
   - It checks every entry: exactly 3 letters A to Z, and a score from 2,500 to 1,000,000.
   - It writes good entries as a new row in the **first tab** of the sheet.
   - When asked for the top 15, it keeps each player's best score and drops the date, so dates stay private.
3. **The Google Sheet** stores every game ever saved. Each row has Initials, Score and Date. Deleting a row removes that entry.

Why the bouncer lives in the sheet and not the game: anyone can open the game's code and change it. The sheet's code can't be changed by players. *Never trust the player's computer.*

Two things found while reading:
- **The 3-letter rule is in the script twice.** Once when saving, once when reading the top 15. If we only change the save check, new 12-letter names would save but never show up. That's a Ghost Bug waiting to happen. Both get changed.
- **The number 15 is written twice:** `LEADERBOARD_SIZE` in the game and `TOP_COUNT` in the script. Part 2 fixes that.

## PHASE 0: Keep notes off the website (separate small change, before anything else)

**Status: done 2026-10-11.** The four CLAUDE pages give 404 on the live site. The home page and pinball still work.

GitHub Pages runs every file through a tool called Jekyll. Jekyll publishes the `.md` files twice: once as-is, and once turned into an `.html` page. Today these all load on digdeeperlabs.com:
- `/CLAUDE.md` and `/CLAUDE.html`
- `/pinball/CLAUDE.md` and `/pinball/CLAUDE.html`

**The change.** Add one new file, `_config.yml`, in the top folder:

```yaml
# Website settings (GitHub Pages).
# Files listed under "exclude" stay in the GitHub repository,
# but they are NOT put on digdeeperlabs.com.
exclude:
  - CLAUDE.md        # the coach handbook in the top folder
  - "*/CLAUDE.md"    # every game's brief, in any folder
  - docs             # plans and notes
```

- The `*` means "any folder", so new game briefs are covered automatically. Nobody has to remember to add each one. That's one source of truth again.
- Nothing else on the site changes. HTML, JavaScript and `lib/` files are still copied as they are.

**Order:**
1. Write `_config.yml`.
2. The parent reviews the diff, then the save point: "Keep notes off the website".
3. After syncing, wait about a minute for GitHub to rebuild, then check:
   - These should give "404 not found": `/CLAUDE.md`, `/CLAUDE.html`, `/pinball/CLAUDE.md`, `/pinball/CLAUDE.html`.
   - These should still work: `/` and `/pinball/`.
4. Only then save this plan into `docs/`, and check that `/docs/2026-10-11-site-v2-plan.md` gives 404 too.

**Reminder:** this hides the files from the website only. Everything in the repo can still be read on GitHub. The safety rules about personal details still apply to every file.

## PART 1: New leaderboard name rule (small, do first)

### Phase 1A: The rule, and the sheet accepts new names
- **Top-level CLAUDE.md** (Safety rules). Replace "Any leaderboard uses initials or gamer tags only" with:
  > Leaderboard names are a first name plus a last initial, or a first name only, 12 characters max. No last names, and no other personal details. Names are trimmed of extra spaces and checked against a basic bad-word list. The parent can delete any entry directly in the Google Sheet.
- **Apps Script.** Tell the parent first, then change:
  - **Name check:** trim the ends and squash double spaces.
    - Allowed: letters only, plus one optional space and one letter at the end ("EMMET", "EMMET G").
    - Pattern: `^[A-Za-z]+( [A-Za-z])?$`, 12 characters max.
    - This pattern rules out last names by itself.
    - Old 3-letter entries still pass, so **existing scores keep showing**.
  - **Same check in `topScores()`,** so new names actually appear. One shared `isGoodName()` function is used in both places. That's one source of truth inside the script.
  - **Bad-word list:** kept in a **"Blocked words" tab** in the sheet, which only the parent edits.
    - Recommended over writing the words into the code. This repo is public, Emmet shouldn't have to write that list, and the parent can add words without redeploying.
    - Matching ignores case and spaces.
  - **Rejections** send a kid-friendly message, like "Try a different name".
  - The JSON field stays `initials` for now. Part 2 renames it.
- **Parent:** add the "Blocked words" tab, then update the deployment to a New version.
- **Test:**
  - The live pinball game still saves a 3-letter name.
  - Existing rows still show.

### Phase 1B: Pinball lets you type 12 characters
- `pinball/physics.js`: add **MAX_NAME_LENGTH = 12** in one place (or in `table.js` with the other dials).
  - `typeInitial()` and `pressEnter()` use it instead of `3`.
  - Allow one Space, only after at least one letter.
  - Enter works once there's 1 letter or more.
- `pinball/sketch.js`: Space types a space while the name box is up. The ball is already over, so the plunger doesn't care.
- `pinball/draw.js` (`drawEnterInitials`): swap the 3 slots for one line of text with a blinking cursor.
  - Change the prompt to "Type your first name + last initial".
  - Check that 12 characters fit on the leaderboard rows. The table is 400 wide, so they fit at size 18.
- `pinball/draw.js` (`drawLeaderboard`): when the sheet rejects a name, show its message and let the player fix the name instead of losing the score.
- **Architect question for Emmet:** ALL CAPS like an arcade machine, or keep the letters as typed?
- **Emmet types:** the `MAX_NAME_LENGTH` line and its comment.
- **Save point:** "Pinball names can be 12 letters".
- Existing scores in the sheet: not touched. The parent fixes those by hand.

## PART 2: One shared leaderboard for every game

**The lesson: one source of truth.** Right now, adding a second game would mean copying the web address, the "offline" logic and the top-15 page into every game. Ten copies means ten places to forget a fix. Instead, every game borrows the same file, like everyone using the same recipe card.

**What is deliberately written twice, and why.** The sheet script keeps its own list of allowed games and score limits. The browser's copy can't be trusted, because the bouncer can't check guests against a list the guest brought with them.

### Phase 2A: Explain and check (no code)
- Walk Emmet and the parent through "How it works today" (above).
- Open the VS Code Apps Script project and compare it with `pinball/leaderboard-script.gs`. If they differ, decide which one is the real one before changing anything.
- Decide where the script's code lives from now on:
  - Recommended: `shared/leaderboard-script.gs` in this repo, kept identical to the Apps Script project.
  - Alternative: point the VS Code Apps Script project at that folder.

### Phase 2B: New sheet script, backward compatible
Tell the parent first. What changes for live pinball: **nothing visible**. Old pinball requests still work.

- **Sheet setup (parent, by hand):**
  - Rename the first tab to `pinball`.
  - The rows stay exactly as they are, so no scores are lost.
- **Script changes:**
  - `GAMES` list: one entry per game, with `minScore` and `maxScore` (pinball: 2,500 to 1,000,000).
    - All ten games are added now, so there's only one redeploy.
    - Unknown games are rejected. Without this, strangers could create junk tabs.
  - A game's tab is created automatically the first time a valid score arrives. Header: Name, Score, Date.
  - `GET ?game=cube-corner` returns `{ topCount, scores: [{ name, score }] }`.
  - `GET ?game=all` returns every game's top 15 in one trip, for the leaderboards page.
  - `POST { game, name, score }` saves a score.
  - **Old-pinball fallback:**
    - A request with no `game` is treated as pinball.
    - `initials` is accepted as `name`.
    - A GET with no `game` answers in the old format.
    - This fallback gets removed later (see the to-do list).
  - Name check and blocked words: same as Phase 1A.
  - `TOP_COUNT = 15` lives only here. Games read `topCount` from the answer.
- **Parent:** New version deploy. **Test:** the live pinball still loads the board and saves a score.
- **Save point:** "Shared leaderboard script". Moves the `.gs` file to `shared/`.

### Phase 2C: `shared/` files, and pinball switches over
- `shared/games.js`: **the list of games.**
  - One entry each: `id` (the folder name), `name`, a one-line blurb, `scoreLabel` ("Coins", "Score", ...).
  - Used by the home page, the leaderboards page and the leaderboard code.
- `shared/leaderboard.js`: **the one place** that knows the web address.
  - `loadLeaderboard(gameId)` and `saveScore(gameId, name, score)` keep the same backpack (`status`, `scores`, `message`) and the same offline timeout as today.
  - `showSaveBox(gameId, score)` puts up a ready-made HTML name box: 12 characters max, Enter to save, and the result shown underneath. It works for all the ported games, which aren't drawn in p5 the same way.
  - `addLeaderboardLink(gameId)` puts the "Leaderboard" link on the page. It opens in a new tab.
- `shared/arcade.css`: shared styles for the How to play box, the name box and the leaderboard link.
- **Pinball changes:**
  - Load `../shared/games.js` and `../shared/leaderboard.js`.
  - Delete `pinball/leaderboard.js`.
  - Send `game: "pinball"` and `name`.
  - Keep its own in-canvas name screen. It already looks great.
- **Emmet types:** the pinball entry in `shared/games.js`.
- **Save point:** "Pinball uses the shared leaderboard".

### Phase 2D: Leaderboards page
- `leaderboards/index.html`:
  - Shows the top 15 for every game, built from `shared/games.js`.
  - Makes one `?game=all` request.
  - With `?game=pinball` in the address, it shows just that game.
  - Names go in with `textContent`, so nobody can sneak code in through a name.
- Pinball's "Leaderboard" link opens `../leaderboards/?game=pinball`.
- `pinball/leaderboard.html` becomes a tiny redirect to that address, so old shared links still work.
- **Save point:** "Leaderboards page".

## PART 3: Bring in Emmet's games

### The recipe for every game (one phase per game)
1. **Get the original.**
   - Download the raw file from the Drive folder. The text reader cut off the ends of three files, so we don't use it.
   - Keep the original outside this repo.
2. **Design chat (no code):**
   - What's the game, in one line?
   - Which score goes on the board?
   - Answer that game's questions (below).
3. **Folder + brief:**
   - `<folder>/CLAUDE.md` with the seven brief sections.
   - Emmet changes at least one thing in it.
   - The original's file name is never written down.
4. **`<folder>/index.html`:**
   - The game code, cleaned so it runs as written.
   - A `TUNING` section at the top for the main dials.
   - Make it into separate files only if that helps. Not required for porting.
5. **Brand scrub:**
   - Titles, on-screen text, comments, variable names and localStorage keys.
   - Rule: **no brand name anywhere in the folder.**
6. **Libraries in `lib/`:**
   - Copy pinball's `p5.min.js` (v1.11.1). The originals used p5 1.4, 1.6 and 1.9, and 1.11 should run their code.
   - If one breaks, we ask before downloading the exact older version.
7. **Saves:**
   - Prefix every localStorage key with the game's folder name.
   - Replace any `localStorage.clear()`. Every game on digdeeperlabs.com shares the same storage, so one game's "Reset" would wipe Pinball and every other game's saves. Each game should remove only its own keys.
8. **How to play box:**
   - First draft from the code's controls (listed below).
   - Then Emmet rewrites it in his own words.
9. **Leaderboard:**
   - Set `GAME_ID` once.
   - Call `addLeaderboardLink(GAME_ID)`.
   - Call `showSaveBox(GAME_ID, score)` at the game's end moment.
10. **Add to `shared/games.js`.** The home page picks it up. Until Part 4, the current home page gets a simple list built from that file.
11. **Test in Chrome**, including saving a score and finding it on the leaderboards page.
12. **Save point.**
