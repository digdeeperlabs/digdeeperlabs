Because this repo is public, this plan says "parent" instead of names, and it leaves out the Drive link and the original file names (some of them are brand names).

## Context

- every game on the site,
- one shared leaderboard all games use,

**How every phase works.** Each phase is small. Each one ends with the site still working and a **save point**. Emmet writes the commit message, clicks Commit, then Sync Changes, then checks the live site. Every feature starts in plan mode with the usual habits:
- the architect questions,

**Live leaderboard rule.** Any phase that changes the Apps Script gets two steps:
- **Before:** Claude tells the parent exactly what will change for the live pinball game.
- **After:** the parent updates the deployment. In Apps Script, go to Deploy > Manage deployments > pencil icon > Version: **New version** > Deploy. Do **not** click "New deployment". That makes a new web address, and the live game would keep calling the old one.

## How the pinball leaderboard works today (plain words)

There are three pieces:

1. **The game** (`pinball/leaderboard.js`) knows one web address: the sheet's web app.
   - To *read*, it asks that address and gets back the top 15.
   - To *save*, it sends `{ initials, score }`.
   - If nothing answers in 8 seconds, it says "Leaderboard offline" and the game keeps going.
2. **The Apps Script** (the copy in the repo is `pinball/leaderboard-script.gs`) is the bouncer at the door.
   - It checks every entry: exactly 3 letters A to Z, and a score from 2,500 to 1,000,000.
   - It writes good entries as a new row in the **first tab** of the sheet.
   - When asked for the top 15, it keeps each player's best score and drops the date, so dates stay private.
3. **The Google Sheet** stores every game ever saved. Each row has Initials, Score and Date. Deleting a row removes that entry.

Why the bouncer lives in the sheet and not the game: anyone can open the game's code and change it. The sheet's code can't be changed by players. *Never trust the player's computer.*

Two things found while reading:
- **The 3-letter rule is in the script twice.** Once when saving, once when reading the top 15. If we only change the save check, new 12-letter names would save but never show up. That's a Ghost Bug waiting to happen. Both get changed.
- **The number 15 is written twice:** `LEADERBOARD_SIZE` in the game and `TOP_COUNT` in the script. Part 2 fixes that.

**Not checked yet:**
- I could not find the leaderboard sheet from the Google account connected here.
- The VS Code Apps Script project is not inside this folder.

So **Phase 2A starts by making sure the live script matches the repo copy.**

**1. CLAUDE.md, Safety rules.** Replace "Any leaderboard uses initials or gamer tags only" with:
> Leaderboard names are a first name plus a last initial, or a first name only, 12 characters max. No last names, and no other personal details. Names are trimmed of extra spaces and checked against a basic bad-word list. The parent can delete any entry directly in the Google Sheet.

**2. `pinball/leaderboard-script.gs`:**
- **New dials at the top:**
  - **MAX_NAME_LENGTH = 12**
  - **SCORE_TAB = "Sheet1"**
  - **BLOCKED_TAB = "Blocked words"**
- **`cleanName(raw)`:**
  - trim the ends,
  - squash runs of spaces into one,
  - **keep the letters as typed.** Emmet's choice: "Emmet G" stays "Emmet G".
- **Same player, any spelling:** the top 15 groups names ignoring upper and lower case. "Emmet G" and "EMMET G" are one player, with one best score. The board shows the spelling from that player's first saved row.
- **`isGoodName(name)`:** **one** check, used both when saving and when building the top 15. That's one source of truth inside the script. A name passes only if all of these are true:
  - It's 1 to 12 characters.
  - It matches `^[A-Za-z]+( [A-Za-z])?$`: a first name, and optionally a space plus one letter. That rules out last names by itself.
  - It doesn't contain a blocked word.
  - Every existing 3-letter row passes, so **all current scores keep showing.**
- **`blockedWords()`:**
  - Reads column A of the "Blocked words" tab, lowercased, spaces removed.
  - If the tab doesn't exist yet, it means "no blocked words", not a crash.
  - Matching: the name with spaces removed is blocked if it *contains* any listed word.
  - Tip for the parent: avoid very short entries. A 3-letter word can hide inside real names.
- **`scoreSheet()`** finds the tab **by name** (`SCORE_TAB`), not "the first tab". Otherwise adding the Blocked words tab in the wrong spot would send every new score into it.
- **Rejection messages** (players see these once Phase 1B shows them):
  - bad format: "Use your first name + last initial, letters only, 12 max"
  - blocked: "Try a different name". It doesn't say which word.
  - score: unchanged.
- **Unchanged:**
  - the `initials` field name (Part 2 renames it),
  - the score limits and top 15,
  - the lock,
  - the dates staying private.
- **`testNames()`:** a function the parent can run from the editor's Run button. It logs pass or fail for sample names: "EMMET", "EMMET G", "ABC", "MAX POWERS", "E G G", "  EMMET   G ", "EMMET1", a 13-letter name and one blocked word. It only runs in the editor. The website can't call it.

**5. Emmet types:** the `MAX_NAME_LENGTH = 12` line and its comment in the script.

## PART 2: One shared leaderboard for every game

**The lesson: one source of truth.** Right now, adding a second game would mean copying the web address, the "offline" logic and the top-15 page into every game. Ten copies means ten places to forget a fix. Instead, every game borrows the same file, like everyone using the same recipe card.

**What is deliberately written twice, and why.** The sheet script keeps its own list of allowed games and score limits. The browser's copy can't be trusted, because the bouncer can't check guests against a list the guest brought with them.

**Script design:**
- **Dials at the top:** `TOP_COUNT = 15`, `MAX_NAME_LENGTH = 12` (Emmet's line, kept), `BLOCKED_TAB`.
- **`GAMES`:** one line per game: `id: { minScore, maxScore }`. The tab name = the id.
  - pinball: 2,500 to 1,000,000.
  - storm-drop-99, cube-corner, burger-stomp, paddle-battle, space-escape, chalk-archer, donut-empire: 1 to 1,000,000,000 for now. Idle games get big numbers. Each one is tuned when the game is brought in.
  - **Not added yet:** the factory and the battleship game. Emmet hasn't picked their final names, and the name becomes the tab. They're added when each one is ported (on the to-do list).
  - Any game not in `GAMES` is rejected, so strangers can't create junk tabs.
- **`setupTabs()`:** the parent runs it once from the editor's Run button.
  - It renames `Sheet1` to `pinball`, so all rows stay.
  - It creates any missing game tab with the header Name, Score, Date.
  - It's safe to run again: it never deletes or overwrites anything.
  - Tabs are made here, by the owner, never by a web request.
- **Reading:**
  - `GET ?game=cube-corner` returns `{ game, topCount, maxNameLength, minScore, scores: [{ name, score }] }`. Games read the limits from the sheet. That's the fix for Emmet's two-places problem, used in 2C.
  - `GET ?game=all` returns `{ topCount, games: { pinball: [...], ... } }` in one trip, for the leaderboards page.
- **Saving:** `POST { game, name, score }` returns `{ ok: true, scores }` or `{ ok: false, error }`.
- **Old-pinball fallback**, so today's live game keeps working:
  - A GET with no `game` returns the old shape: the pinball list as `[{ initials, score }]`.
  - A POST with `initials` and no `game` is treated as pinball and answered in the old shape `{ ok, top: [{ initials, score }] }`.
  - Removed later (to-do), once pinball uses the new shape in 2C.
- **`testNames()`:** kept, plus a few game checks.
  - An unknown game is rejected.
  - A cube-corner score of 0 is rejected, and 1 is OK.
  - A pinball score of 2,000 is rejected.
